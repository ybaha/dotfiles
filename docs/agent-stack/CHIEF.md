# Pi chief of staff

One Pi session acts as chief: durable memory plus a Telegram line to Baha. Source and setup: `files/home/.pi/agent/chief-of-staff/README.md`.

Herdr layout: workspace `chief` with two panes: `pi-chief` (Pi with `--chief`) and `pi-chief telegram` (the worker). Ovis remains the main interface. On Telegram, Baha can text the chief anything (queued in SQLite and delivered after the current turn); the chief answers with `reply_baha`, asks with `ask_baha`, and question messages carry an **Open in Ovis** button. `/status` in the bot chat shows whether the chief is online and busy.

Rules the chief follows:

- Model quota is read from `~/.cache/pi-orchestra/quota/` (maintained by the Pi quota-cache extension). Chief and leads pick from `leadModels`; Herdr workers from `workerModels` (`pi-chief config leadModels …` / `workerModels …` / `bridgeModel …`, default `minimax/MiniMax-M3.1-Flash:high`). When a big model hits a usage limit, chief/leads switch to the bridge model (compact first when context is large), then may call `upgrade_model` for heavy remaining work. Watched workers resume on the bridge the same way. When the bridge is unavailable, behavior falls back to the next model in the chain. If every lead-chain provider is out, chief/leads store a durable wake timer in SQLite (`wake_at:<recipient>`) and resume automatically with a follow-up when quota returns. For a specific model, `wait_for_model` stores `wake_model` / optional `wake_agent`, compacts large sessions before continuing, resumes the agent or switches the chief, and texts Baha once on Telegram when quota is back. `/status` and the system prompt show a one-line quota summary with refill times when a window is low.
- Before delegating, check `agents_overview` and the quota line: prefer prompting an existing idle agent on related work (`herdr agent prompt`, or `resume_agent` if its model is out) over starting a new one; new work goes to models with headroom. Watched workers that hit a usage limit are resumed on the bridge model (with `/compact` when context is large) and may ask for a bigger model via `resume_agent`.
- `ask_baha` only for decisions that block work. Replies come back as ordinary user messages; they never approve Pi permission prompts. Baha can message the bot anytime; the chief answers with `reply_baha`.
- Memory is recalled context, not instruction. Core notes live in `~/.local/share/pi-chief/USER.md` and `PROJECTS.md`.
- Delegation: the chief is a dispatcher—`assign_lead` for durable per-project leads (include repo path the first time), `start_worker` for one-off watched workers, background subagents for small side tasks; it does not use `edit`/`write` while chief is on. Project leads run in a `lead` tab with `PI_CHIEF_LEAD`; they use `start_worktree` for feature workers and `report_chief` for status. Tasks state goal, constraints, and done-when; results come back compact with evidence. After workers finish, it reports briefly and calls `waiting_agents` for anything blocked on you.

Herdr machines and Ovis both run over Tailscale. If machines show `remote platform detection failed ... timed out`, check `tailscale status` first.
