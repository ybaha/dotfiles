# Restart Pi agents on hc

This restarts Pi, not hc, and does not install updates. Terminal addresses change; names, cwd, `herdr.space`/`herdr.tab`, `ovis.*` and `dotfiles.worker` ownership labels survive. Do not restart remote machines implicitly. Never use `--continue`, fresh sessions, or dismiss blocked dialogs.

1. Read `hc --skill` and check `hc run --help`. Require `hc`, `pi` on the caller's PATH and `HC_TERMINAL_ID` (not an old pane ID).
2. Resolve `scripts/restart.py` relative to this skill. Run `python3 <script>` for inventory only. It filters local live Pi terminals from `hc ls`, gets launch details with `hc get`, and never reads session-file contents. `restartable_launcher` checks launcher safety, not current provider readiness or permission to interrupt.
3. Only terminals whose own launch is Pi (literal argv executable basename `pi`, or a simple `sh -c … exec pi` wrapper) **and** whose observed agent is Pi may be replaced. Shell-hosted Pi, opaque/node launchers, wrappers without exec and unsupported launch options are skipped with a manual-restart message. Apply returns nonzero for skipped targets. No override bypasses launcher validation: never quit a terminal the helper cannot replace. Inspect `hc get/read` and restart unsupported launchers manually.
4. Tell the user the eligible count and explain interruption of active turns. Ask if interruption authority is unclear. Blocked/error/unknown agents are never dismissed. Also explain that authoritative session identity is available only after quit: if the exit resume line is missing or its session file cannot be verified, Pi remains stopped and requires manual recovery. Launch argv and newest-file timestamps cannot identify the current session after `/new`, `/fork` or `/resume`.
5. Run `python3 <script> --apply` for all agents **except the caller**, adding `--interrupt` only when authorized. The helper rechecks launcher/agent identity before input, uses `hc interrupt` if needed, sends `/quit`, and verifies the terminal finished. It then reads `hc read --lines 40 <t>` and takes the **last** `To resume this session: pi --session <id-or-path>` match. That exact token is passed to the replacement's `--session`; IDs are resolved under `~/.pi/agent/sessions/--<encoded-cwd>--/` only to verify an existing unique file. A path is checked relative to the preserved cwd or as an absolute path. No argv/mtime fallback is used.
6. Replacements use `hc run --bg --no-parent --name … --cwd … --label …`. Unnamed terminals remain unnamed. The shell command uses the caller-resolved Pi executable and prepends its bin directory to PATH (required for nvm on macOS). If the exit line is missing/unresolvable or cannot be read, **no replacement starts**; the failure identifies the stopped terminal, cwd and candidate files (not selected) for manual recovery. A custom session-directory ID outside the cwd's normal session directory needs manual recovery unless Pi prints an existing path.
7. Inspect failures with `hc get <t>` / `hc read --lines 80 <t>`; do not blindly retry the whole fleet. A startup failure may already have launched a replacement. Never bypass trust prompts. Finished originals remain recovery evidence. Only after every other restart succeeds, make the final tool action `python3 <script> --schedule-current`. A separate `hc run --bg --no-parent` helper validates the caller's launcher, waits up to 180 seconds for the response to finish, then quits and reads its authoritative exit session by the same procedure. Its manifest does not freeze a guessed session. It survives the caller quitting; its temporary result log records success/failure.
8. End promptly with a short report of verified replacements, stopped/skipped failures, and the caller **scheduled** last, not already verified. If anything failed, leave the caller running until resolved.

The script verifies replacement cwd and session launch arguments, not model/provider readiness. No live restart is part of dotfiles tests. Reload existing sessions to discover changed skills/prompts only after subagents finish.
