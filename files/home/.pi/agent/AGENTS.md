# Personal Pi operating rules (all working directories)

- Follow the current repository's `AGENTS.md` and local instructions for project-specific work. Do not assume optional repositories exist on this machine.
- Herdr owns durable workspaces/panes; Pi owns the agent session; pi-subagents are temporary children, not Herdr panes. Use one durable agent per workspace/tab/pane and one writer per worktree unless the user requests otherwise.
- Do not open new Herdr tabs, panes, or workspaces for agents or helpers; reuse the existing durable agent in the current pane. Exception: the Telegram tab in the Chief workspace. Pi background subagents need no Herdr UI. Helpers such as `assign_lead`, `start_worker`, and `/skill:worktree` must not silently spawn extra tabs—if no suitable pane exists, use a background subagent or ask the user. Do not close or reorganize Herdr tabs without explicit user approval.
- Keep the main session responsive: start subagents with `run_in_background: true`, continue independent work, and use completion notifications rather than polling or `get_subagent_result(wait: true)`. If only child results remain, give a short status and yield instead of waiting inside a tool. Use blocking calls only for a genuine immediate dependency when no useful parallel work is possible.
- When operating inside Herdr, consult `herdr --skill` before controlling workspaces, panes, agents, or plugins if a Herdr skill is not already available. Herdr plugins are separate from Pi skills and extensions; check `herdr plugin list`/`herdr plugin action` rather than assuming a plugin is installed.
- Use `/skill:worktree` for an isolated Herdr worktree when available. Its source is the global skill in the dotfiles repo.
- Where configured, use `claude-bridge` for Claude (not the direct Anthropic API), `cursor-ide/composer-2.5` for approved implementation (not Cursor's agent CLI or fast variant), and MiniMax only for fixed-scope mechanical tasks with review. Before substantial delegation, check quota with `bash ~/.pi/agent/extensions/quota-status.sh` and verify the selected provider is available.
- Keep the machine responsive: run tests one-shot (`vitest run`, `CI=1`), never in watch mode; wrap long commands in `timeout`; do not background jobs with `&` or pipe them to `tail`; and do not start a test run if one for the same project is already running (check with `pgrep`). Stop every process you start before finishing, and never stop one you did not start.
- Do not put credentials in repositories or prompts. Keep Pi auth local in `~/.pi/agent/auth.json`. Ask before installing/updating integrations, packages, or plugins on a machine.

When relevant, consult the short guides in the dotfiles repo's `docs/agent-stack/`; do not load them for every task.
